01

Dify 是什麼、不是什麼

AN ASSEMBLY PLATFORM FOR LLM APPS

它不是另一個 ChatGPT，也不是一個模型。它是把 LLM、知識庫、外部工具與流程邏輯「組裝」起來的地方——只做推論＋提示，不做訓練。

06

抑制幻覺的手法與 Prompt 的約束力

WHAT PROMPTS CAN — AND CAN'T — GUARANTEE

需要「保證」的東西不能只靠 Prompt：數值計算一律用工具查表或計算；事實正確性接知識庫＋標註來源；數量限制用流程節點驗證。

① 階層式任務拆解辨識 → 檢索 → 判斷分級 → 生成建議；不給步驟，中間推理是事後補編的
② Few-shot 範例2–3 個「輸入 → 標準輸出」；範例比規則有效（SOAP、ISBAR）
③ 輸出格式約束強制 Red Flags 欄位；更保險：交給模板轉換節點
④ 找不到就說找不到★ 給替代動作——只寫「不要編造」效力很弱

這個要求，Prompt 管得住嗎？

RAG 四步與切塊大小

CHUNK · EMBED · RETRIEVE · GENERATE

品質瓶頸幾乎都在第 ③ 步：LLM 只看得到「被召回的那幾段」。召回錯了，生成再厲害也沒用——這也是為什麼一直改 Prompt 常常沒有效果。

切塊模擬器：「CMS 第 4 級每月給付額度是多少？」

核心互動

示範文件為依講義數字編寫的簡短給付基準（以衛福部最新公告為準）；字數按比例縮小。

08

召回設定：Top-K、相似度閾值、Rerank

RETRIEVAL SETTINGS · HYBRID SEARCH

Top-K 與閾值是「且」的關係：要進 Prompt，必須同時過閾值、又排進前 K。實務起點：Top-K 3–5、閾值 0.5；法規條號、藥名用混合檢索。

程式碼節點與變數綁定

CODE NODE · VARIABLE BINDING

連線決定「順序」，變數綁定才決定「內容」。最常見的失敗：變數沒綁 → 下游收到空值 → LLM 沒有資料可用 → 開始自由發揮——看起來像幻覺，其實是接線問題。

除錯決策樹：答案不對時依序檢查什麼

異常處理與 Fallback
