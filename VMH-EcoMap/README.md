## 這是什麼

VMH-EcoMap 是一套三軸式顧問工具，用來回答「一整座越南現代醫院的生意」該怎麼拆、誰來做、什麼時候做、做到什麼程度才算合格：

| 軸 | 問的問題 | 內容 |
|---|---|---|
| **C 軸** 能力模組 | 能做什麼？缺什麼？誰能做？ | 10 大領域 D01–D10，60 項能力 |
| **A 軸** 階段路徑 | 先後順序？何時做？ | Stage-Gate G0–G6，60 個月，20 個工作包 |
| **B 軸** 法規門檻 | 做到什麼程度才算合格？ | 越南強制法規 11 條 ＋ 國際標準 26 條 |

三軸交會的每一格＝某個領域在某個階段的具體商機。

原本這套工具是一份 21 個分頁的 Excel。這個網站是它的**線上發布層**：把同一份資料變成可搜尋、可連結、可回溯的知識庫。

**為什麼要有這一層**：Excel 很擅長計算與模擬，但不擅長散布與留痕。用 LINE 傳檔案，收件人拿到的永遠是一份快照，而且沒有人知道是誰在什麼時候改了什麼。詳細評估見 [`docs/知識管理系統評估報告.md`](docs/知識管理系統評估報告.md)。

## 怎麼更新（每週只做這四步）

Excel 仍然是**唯一的輸入處**，網站是**唯一的發布處**。

```bash
# 1. 照舊在主工具 Excel 的「03 能力總表」改資料
#    （黃色儲存格＝可編輯；其餘是公式，會自動連動）

# 2. 把新版 Excel 放進 source/
cp ~/Downloads/VMH-EcoMap-1_主工具_v1.1.xlsx VMH-EcoMap/source/

# 3. 轉檔（21 個分頁 → data/*.json）
cd VMH-EcoMap
pip install openpyxl            # 只需第一次
python3 tools/xlsx_to_json.py   # 不給參數＝自動取 source/ 裡最新的 .xlsx

# 4. 送上去，網站即時更新，這一版的差異自動進入歷程
git add -A
git commit -m "VMH-EcoMap 資料更新至 v1.1：補上 CAP-028 候選夥伴"
git push
```

第 4 步就是「保存與看到修改歷程」的機制：**每一次更新都是一次 commit**，
誰在什麼時候改了哪一行，永久可回溯、可比對、可還原。

歷程可以在這裡看：
<https://github.com/NCHSIEH/nchsieh.github.io/commits/main/VMH-EcoMap/data>

## 本機預覽

網站用 `fetch()` 讀 JSON，直接用 `file://` 開啟會被瀏覽器擋下，要起一個本機伺服器：

```bash
cd VMH-EcoMap
python3 -m http.server 8000
# 開啟 http://localhost:8000/
```

## 網址就是分享方式

不要再傳檔案，傳連結。每一個知識物件都有自己的永久網址：

| 想給對方看 | 網址 |
|---|---|
| 某一項能力的完整體檢表 | `#/cap/CAP-028` |
| 某一門生意的作戰卡 | `#/opp/OPP-24` |
| 某個夥伴被指名的所有工作 | `#/partner/P-001` |
| 缺口招募清單（可當 RFI） | `#/gaps` |
| 只看醫材領域的能力 | `#/caps?domain=D05` |
| 只看缺口 | `#/caps?puzzle=缺口-待尋找` |

例：`https://nchsieh.github.io/VMH-EcoMap/#/cap/CAP-028`

## 使用上的操作

- **⌘K**（Mac）或 **Ctrl+K**（Windows）或 **/** — 全站搜尋，打穿所有分頁
- 右上角 **☾ / ☀** — 深淺色切換（會記住）
- 每個清單頁上方都有篩選列；列印時會自動隱藏導覽與篩選

## 重要聲明

- 本工具為**顧問規劃用途**，不構成法律意見、投資報價或設施設計。
- 工具內的**時程、金額與評分多為規劃假設值（示意）**。正式評估前每一筆都必須以廠商報價、在地查證或現地量測取代，並在來源清冊登錄出處。
- 目前 60 項能力的**證據成熟度全部是「推測 Assumption」**，其中 19 項已判為「立即推進 Go」。在證據沿階梯上爬之前，這些項目不可以對越南官方或投資方做出承諾。
- **越南法規以官方越南文版本為準**，來源清冊中的英譯僅供參考。11 條強制法規目前狀態全部是「待確認」。
