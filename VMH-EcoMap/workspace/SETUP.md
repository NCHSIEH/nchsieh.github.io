# 專案協作區 — 啟用設定

程式已經寫好並測試過了，但**還不能用**，因為 Firebase 那邊有三件事必須由你在 Console 操作。
照下面做完（約 10 分鐘），網址就能開：

**<https://nchsieh.github.io/VMH-EcoMap/workspace/>**

---

## 為什麼檔案不是放 GitHub

你的網站 repo 是**公開**的。課程講義放 GitHub 沒問題（本來就要給學生看），
但業主的文件放上去等於全世界都能下載。

所以協作區的檔案改放 **Firebase Storage**，由存取規則擋人：
沒登入、沒被你核准、或已被暫停的人，連檔名都拿不到。

---

## 步驟 1：啟用 Firebase Storage

1. 打開 <https://console.firebase.google.com/> → 選 **nchsieh-lms** 專案
2. 左側選 **Build → Storage**
3. 按 **Get started（開始使用）**
4. 安全規則那一步選 **Start in production mode**（正式模式）——先擋光，等一下貼我們自己的規則
5. 位置選 **asia-east1（台灣）** 或 **asia-southeast1（新加坡）**，離越南近
6. 按 **Done**

> **關於費用**：Firebase 目前要求啟用 Storage 時綁定 Blaze 方案（需要信用卡）。
> Blaze 有免費額度：**每月 5 GB 儲存、1 GB/天 下載**。
> 顧問專案的文件量距離這個額度非常遠，實際上不會產生費用。
> 如果不想綁卡，跟我說一聲，我可以改成「只記版本紀錄、檔案放你的 Google Drive 連結」的做法。

---

## 步驟 2：貼上 Storage 安全規則

**這一步是機密檔案的唯一防線，不能跳過。**

1. Storage 頁面上方選 **Rules（規則）**
2. 把編輯區內容**全部刪掉**
3. 打開專案裡的 **`storage.rules`**，全部複製貼上
4. 按 **Publish（發布）**

---

## 步驟 3：更新 Firestore 規則

1. 左側 **Build → Firestore Database** → 上方 **Rules（規則）**
2. 全部刪掉
3. 打開專案根目錄的 **`firestore.rules`**，全部複製貼上
4. 按 **Publish（發布）**

> 這份規則檔已經包含你原本課程系統的所有規則，**新增**協作區那一段。
> 直接整份覆蓋即可，不會影響現有的學生與課程功能。

---

## 步驟 4：建立你自己的帳號

1. 開啟 <https://nchsieh.github.io/VMH-EcoMap/workspace/>
2. 按「還沒有帳號？註冊」
3. 用 **nchsieh@gmail.com** 註冊（這個 Email 在 `config.js` 的管理者名單裡，會自動成為顧問身分，不需要核准）
4. 登入後應該會看到四個分頁：**動態 / 檔案 / 訊息 / 成員**

看得到「成員」分頁就代表全部設定成功了。

---

## 之後怎麼邀請業主

1. 把網址給對方：<https://nchsieh.github.io/VMH-EcoMap/workspace/>
2. 對方自己註冊（填 Email、密碼、姓名、單位）
3. 你到 **成員** 分頁按 **核准**
4. 核准前，對方看到的只有「帳號審核中」，**拿不到任何檔案或訊息**

不再合作時按 **暫停**，資料留著但立刻失去存取權。

## 怎麼用

### 檔案與版本控制

- **新增文件**：一份文件 = 一個「東西」，例如「越南醫院可行性評估報告」。
  **檔名不要放版號**，版號由系統管。
- **上傳新版本**：每上傳一次就是一個新版本（v1、v2、v3…）。
  **一定要填「這一版改了什麼」**——三個月後你自己也會需要那句話。
- **舊版永遠留著**：每一版都能單獨下載，不會被新版覆蓋。
- 版本紀錄一旦建立就**不能修改**（規則層擋住），確保歷程可稽核。

### 訊息

取代 LINE 的地方。重要的事寫在這裡，永遠找得回來，而且可以接著討論。
標「重要」的訊息在列表上會有紅色標記。

### 動態

按時間順序記下每一次檔案更新與每一則訊息——**誰、什麼時候、改了什麼**。
業主問「這兩週推進了什麼」，把這一頁給他看就好。

## 疑難排解

| 狀況 | 原因與處理 |
|---|---|
| 「權限不足」或「Missing or insufficient permissions」 | 步驟 2 或 3 的規則沒發布，或發布後還沒生效（等 1 分鐘） |
| 上傳時出現「沒有檔案存取權限」 | Storage 規則沒貼，或帳號還沒被核准 |
| 註冊後一直停在「帳號審核中」 | 正常。要由顧問（你）到成員分頁核准 |
| 看不到「成員」分頁 | 你登入的 Email 不在 `assets/js/config.js` 的 `ADMIN_EMAILS` 裡 |
| 頁面一片空白 | 開瀏覽器主控台（F12）看錯誤訊息，多半是 Firebase 設定或規則問題 |

---

## 要新增其他管理者

兩個地方都要改，缺一不可：

1. `assets/js/config.js` 的 `ADMIN_EMAILS`
2. `firestore.rules` **和** `storage.rules` 裡的 `adminEmails()` 函式

改完 rules 要重新發布。兩邊不一致會出現「看得到後台但存不了檔」。
